# 銀行後台管理系統

以 Java 17 撰寫的銀行後台管理系統命令列原型。程式以選單提供客戶、帳戶與交易操作，並記錄重要異動供稽核。此專案目前使用記憶體保存資料，適合功能示範與開發練習。

## 功能

### 客戶管理

- 新增客戶：建立姓名、電話、電子郵件資料並產生客戶編號。
- 查詢客戶：依客戶編號查詢，或以姓名片段搜尋。
- 修改客戶：更新姓名、電話與電子郵件。
- 刪除客戶：客戶仍有帳戶時拒絕刪除，避免帳戶失去所屬客戶。

### 帳戶管理

- 開立帳戶：帳戶必須關聯已存在的客戶，初始餘額為 0。
- 查詢帳戶：顯示帳戶編號、所屬客戶、餘額與啟用狀態。
- 查看餘額。
- 停用帳戶：僅允許餘額為 0 的帳戶停用；停用後不可再交易。

### 交易

- 存款與提款。
- 帳戶間轉帳。
- 查詢指定帳戶最近三個月的交易，依時間由新到舊顯示。
- 金額必須大於 0，最多兩位小數；提款和轉帳會檢查餘額。

金額使用 `BigDecimal` 運算，避免使用二進位浮點數造成金額精度誤差。交易操作由同步方法保護，避免同一個 `Bank` 執行個體上的並行呼叫同時修改餘額。

### 稽核紀錄

新增、修改、刪除客戶，開立及停用帳戶，以及存款、提款與轉帳都會建立稽核紀錄。每筆紀錄包含時間、操作、主體、內容、前一筆雜湊與本筆 SHA-256 雜湊；主選單的「稽核紀錄」會列出紀錄並驗證雜湊鏈。

稽核資料目前只存在程式記憶體中。雜湊鏈可協助偵測紀錄內容或鏈結遭修改，但程式重新啟動後資料會清空；正式環境應改用持久化儲存、限制存取權限，並將稽核資料寫入受保護的追加式儲存媒介。

## 交易查詢效能設計

交易以「帳戶 → 時間排序索引」儲存。查詢最近三個月時，先透過 `TreeMap` 範圍查找時間區間，再讀取區間內的交易，預期成本為 **O(log n + k)**；其中 `n` 是該帳戶的交易數，`k` 是查詢結果筆數。因此不需逐筆掃描全體交易。轉帳會同時索引到轉出與轉入帳戶。

專案尚未加入百萬筆交易的負載測試，故此複雜度設計並非實際量測或一秒回應時間保證。實際效能仍取決於資料量、硬體、記憶體與結果筆數。

## 環境需求

- JDK 17 或以上
- Apache Maven（使用 Maven Wrapper 時可不另行安裝 Maven；本專案目前未包含 Maven Wrapper 執行腳本）

Maven 會依 `pom.xml` 下載 JUnit 5 與 Surefire 等建置依賴。若 `mvn` 已在 `PATH`，可直接使用下列命令。

## 執行

在專案根目錄編譯並啟動：

```bash
mvn compile
java -cp target/classes org.example.Main
```

啟動後依主選單輸入編號，再依提示操作。範例流程：新增客戶、開立帳戶、存款，然後查詢餘額或交易紀錄。客戶與帳戶編號會在建立時輸出，後續操作需輸入該編號。

## 執行單元測試

```bash
mvn test
```

`src/test/java/org/example/WithdrawalTest.java` 使用 JUnit 5 測試三個提款情境：

1. 餘額 10,000 元提款 3,000 元，提款成功，餘額為 7,000 元。
2. 餘額 10,000 元提款 15,000 元，提款失敗，餘額維持 10,000 元。
3. 餘額 10,000 元提款 10,000 元，提款成功，餘額為 0 元。

測試會在每個情境前建立獨立銀行、客戶與帳戶，並存入 10,000 元作為起始餘額。

## 目前範圍與限制

- 資料僅儲存在記憶體，結束程式後不保留。
- 這是命令列原型，沒有網頁介面、HTTP API、登入驗證、角色權限或資料庫。
- 尚無交易明細分頁、日期區間自訂、利息、手續費或幣別設定。
- 最近三個月的查詢實作為從現在時間往前推三個月，依執行環境時區轉換。
- 稽核雜湊鏈沒有外部錨定或簽章，因此無法防止具備程式記憶體存取權限者重建整條鏈。
